# English

Self-contained monolithic architecture template: Express serves both static frontend assets and SHOPLINE OAuth routes from the same process. All backend modules are included in `lib/` — no external references required.

## Directory Structure

```
integrated/
├── app.js                     # Entry point — mounts routes, middleware, static files
├── package.json               # Dependencies and build scripts
├── routes/
│   └── auth.js                # /app/homepage · /app/callback · /webhook/appstore/callback
├── lib/
│   ├── sign.js                # HMAC-SHA256 signature verification and generation
│   ├── session_token.js       # Session JWT generation, parsing, and decoding
│   ├── token_store.js         # Pluggable token storage (memory / Redis / DB)
│   ├── callback.js            # GET /app/callback — OAuth code exchange handler
│   ├── homepage.js            # GET /app/homepage — entry point and redirect logic
│   ├── webhook.js             # POST /webhook/appstore/callback — lifecycle events
│   └── middleware.js          # JWT session auth middleware for protected routes
├── src/
│   └── shopline-auth.js       # Frontend auth SOURCE (esbuild bundles to public/js/)
├── public/
│   ├── index.html             # App home page HTML
│   └── js/
│       └── shopline-auth.js   # Bundled output (generated by: npm run build)
├── .env.example               # Environment variable template
└── README.md
```

## Quick Start

### 1. Install Dependencies

```bash
npm install
```

> The `package.json` already declares all required dependencies: express, dotenv, axios, jsonwebtoken, express-rate-limit, @shoplineos/app-bridge, esbuild.

### 2. Configure Environment Variables

```bash
cp .env.example .env
```

Edit `.env` with real values:

```env
APP_KEY=your_app_key
APP_SECRET=your_app_secret
APP_NAME=my-shopline-app
APP_SCOPES=read_orders,write_orders
APP_HOME_URL=https://my-app.example.com   # Full URL (include https://)
PORT=3000
```

### 3. Replace Stub Functions

Open `routes/auth.js` and replace the following functions with your real implementations:

| Function | Description |
|----------|-------------|
| `loadApp(appKey)` | Query app configuration from database |
| `loadStoreApp(appKey, handle)` | Query store installation record |
| `persistRefreshToken(handle, storeID, tokenData)` | Write refresh token to database |
| `markUninstalled(handle, appKey)` | Set installation status to false |

Also update the stub loaders in `app.js` (`loadApp` and `checkInstall`) for the auth middleware.

### 4. Start the Server

```bash
node app.js
# Output: [shopline-auth] integrated server listening on port 3000
```

### 5. Verify Endpoints Are Accessible

```bash
curl http://localhost:3000/health
# Expected: {"status":"ok"}

# Frontend auth script should be accessible:
curl http://localhost:3000/js/shopline-auth.js
```

## Frontend Integration

The template includes a ready-to-use `public/index.html`. The bundled `shopline-auth.js` already contains `@shoplineos/app-bridge` (v0.0.1) — **do NOT load the CDN app-bridge.js separately**.

```html
<!-- App Bridge is bundled inside shopline-auth.js via esbuild — no CDN needed -->
<script src="/js/shopline-auth.js"></script>
```

To rebuild after editing `src/shopline-auth.js`:

```bash
npm run build
```

The script handles three cases automatically:

| Scenario | Behavior |
|----------|----------|
| Embedded app, not installed (`uninstalled=true`) | App Bridge redirects to OAuth page |
| Authorized (`token` in URL) | Stores token, provides `authenticatedFetch()` |
| External app / other | No-op (backend handles 302 redirects) |

After authorization, use `authenticatedFetch()` for API calls:

```javascript
const res = await authenticatedFetch('/api/me');
const data = await res.json();
```

## `lib/` Module Reference

| Module | Exports | Description |
|--------|---------|-------------|
| `sign.js` | `verifySign`, `generatePostSign`, `verifyTimestamp` | HMAC-SHA256 signature utilities |
| `session_token.js` | `generateSessionToken`, `parseToken`, `decodePayload` | Session JWT operations (HS256) |
| `token_store.js` | `getAccessToken`, `MemoryTokenStore`, `accessTokenKey`, `computeTTL`, `set`, `del`, `get` | Pluggable token cache |
| `callback.js` | `callbackHandler`, `exchangeToken`, `refreshToken`, `extractStoreID` | OAuth code→token exchange |
| `homepage.js` | `homepageHandler`, `buildAppHomeURL` | Install detection + redirect logic |
| `webhook.js` | `webhookHandler` | App lifecycle event handler |
| `middleware.js` | `authMiddleware` | JWT auth middleware for `/api/*` routes |

## Register on SHOPLINE Developer Platform

| Configuration | Value |
|---------------|-------|
| App home page URL | `https://<APP_HOME_URL>/app/homepage` |
| Authorization callback URL | `https://<APP_HOME_URL>/app/callback` |
| Webhook (app uninstall) | `https://<APP_HOME_URL>/webhook/appstore/callback` |

> All URLs must use HTTPS and be publicly accessible.

## Verify the Authorization Flow

1. Find your app in the SHOPLINE test store admin panel and click **Install**.
2. Check server logs to confirm `/app/homepage` received the request and signature verification passed.
3. After the merchant authorizes, confirm `/app/callback` received the request and the log shows successful token exchange.
4. The final redirect should set an HttpOnly Secure cookie `session_token` (the token is no longer exposed in the URL).

## Production Notes

- `APP_SECRET` must only exist in server environment variables — never write it into code or logs.
- Replace the in-memory token cache with Redis (see the replacement example in `lib/token_store.js`).
- Use an HTTPS reverse proxy (nginx / Caddy) to forward port 80/443 traffic to this service. The template already sets `app.set('trust proxy', 1)` so that `express-rate-limit` reads the real client IP from `X-Forwarded-For` instead of the proxy's IP. If you remove or change the proxy topology, adjust this value accordingly.

## 前端集成

模板已包含可直接使用的 `public/index.html`。打包后的 `shopline-auth.js` 已内含 `@shoplineos/app-bridge`（v0.0.1）——**不要额外加载 CDN 的 app-bridge.js**。

```html
<!-- App Bridge 已通过 esbuild 打包在 shopline-auth.js 中，无需 CDN -->
<script src="/js/shopline-auth.js"></script>
```

修改 `src/shopline-auth.js` 后重新构建：

```bash
npm run build
```

脚本自动处理三种情况：

| 场景 | 行为 |
|------|------|
| 内嵌应用，未安装（`uninstalled=true`） | 通过 App Bridge 跳转 OAuth 授权页 |
| 已授权（URL 含 `token`） | 存储 token，提供 `authenticatedFetch()` |
| 外跳应用 / 其他 | 无操作（后端直接 302 重定向） |

授权完成后，使用 `authenticatedFetch()` 进行 API 调用：

```javascript
const res = await authenticatedFetch('/api/me');
const data = await res.json();
```

## 授权流程验证

1. 在 SHOPLINE 测试店铺后台找到你的应用，点击 **安装**。
2. 检查服务日志，确认 `/app/homepage` 收到请求并签名验证通过。
3. 商家授权后确认 `/app/callback` 收到请求，日志显示 token 换取成功。
4. 最终重定向应设置 HttpOnly Secure cookie `session_token`（token 不再暴露在 URL 中）。

## 生产注意事项

- `APP_SECRET` 只存在于服务器环境变量，禁止写入代码或日志。
- 将内存 token 缓存替换为 Redis（见 `lib/token_store.js` 中的替换示例）。
- 使用 HTTPS 反向代理（nginx / Caddy）将 80/443 流量转发至本服务。模板已设置 `app.set('trust proxy', 1)`，使 `express-rate-limit` 从 `X-Forwarded-For` 读取真实客户端 IP 而非代理 IP。若移除或更改代理拓扑，请相应调整该值。
